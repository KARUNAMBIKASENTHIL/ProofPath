# Learning Path: Java Backend Development

## Intended outcome
A learner can build, test, document, and deploy a database-backed REST API using Java and Spring Boot.

## Stage 1 — Core Java
Topics: variables, control flow, methods, arrays, strings, classes, OOP, interfaces, exceptions, collections, generics.
Practice: small programs and problem-solving exercises.
Exit evidence: runnable Java programs with input handling and explanations of key design choices.

## Stage 2 — DSA and complexity
Topics: arrays, strings, hash maps/sets, stacks, queues, linked lists, trees, sorting/searching, Big-O.
Practice: solve role-relevant problems and explain time/space complexity.
Exit evidence: tested solutions with edge cases and understandable reasoning.

## Stage 3 — SQL and data modeling
Topics: tables, primary/foreign keys, joins, constraints, normalization basics, transactions, indexes.
Practice: design a small schema and write queries for realistic requirements.
Exit evidence: schema diagram, sample data, queries, and explanation of relationships.

## Stage 4 — HTTP and REST
Topics: request/response, methods, status codes, JSON, resource naming, validation.
Practice: design endpoints for a small service before implementation.
Exit evidence: API specification or endpoint table with example requests/responses.

## Stage 5 — Spring Boot application
Topics: controllers, services, repositories, dependency injection, configuration.
Practice: build CRUD endpoints connected to a database.
Exit evidence: complete API that runs locally and persists data.

## Stage 6 — Reliability and testing
Topics: input validation, centralized exception handling, unit tests, integration tests, logging.
Practice: test valid requests, missing fields, invalid IDs, and database failures.
Exit evidence: test suite and consistent error responses.

## Stage 7 — Security and delivery
Topics: authentication/authorization basics, password handling, environment variables, secrets, deployment.
Practice: protect selected endpoints and deploy a demo.
Exit evidence: safe configuration, documented setup, deployed endpoint or reproducible deployment steps.

## Personalization rules
- If Java/OOP evidence is weak, begin at Stage 1.
- If algorithms are strong but there is no API project, prioritize Stages 4–5.
- If CRUD works but edge cases fail, prioritize Stage 6.
- If local execution works but there is no delivery evidence, prioritize Stage 7.
